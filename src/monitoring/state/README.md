# 错误收据与原子提交

本目录维护单个接收实例，不启动来源调用或决定目标健康。公开接口由[monitoring](../README.md)导出。

- `mod.rs` 生成绑定请求，维护来源时效与覆盖，以稳定身份哈希创建独立 ErrorLog，并原子提交收据和检查点。持久提交成功后发布视图并唤醒消费者。
- `checkpoint.rs` 绑定配置与协议语义，恢复代次、游标和序号，从全部持久 ErrorLog 重建去重；不继承运行期来源新鲜度。
- `validation.rs` 在任何状态变更前校验整批身份、顺序、限额以及与持久历史的内容一致性。相同身份仅允许 age_ms 变化，不可变冲突整批拒绝。

接收状态没有健康规则或连续阈值。Coverage 是来源问题，不能改写 ErrorLog。完整空批刷新来源接收时刻，可恢复覆盖，不解除收据；重复批同游标无状态变化时不追加持久日志。来源代次保留上限耗尽后明确拒绝新代次，不遗忘旧代次后接受重放。

轮询、取消和成员在场有效性由 scheduler 管理。查询、持久提交和正常关闭共用登记门；错误收据、检查点及视图不能跨门暴露半提交状态。

验证见[集中监控测试](../../../tests/monitors.rs)及[网络接入测试](../../../tests/monitor_wire.rs)，规则见[AGENTS](AGENTS.md)。
