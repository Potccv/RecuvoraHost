# 监控模块开发规范

继承 [源码模块规范](../AGENTS.md)。职责与状态见 [README.md](README.md)，接口遵循 [插件规范](../../docs/extensions/README.md)。

## 本域约束

- 本目录维护宿主侧监控契约、消费者、代理和外部节点接入要求；具体日志、进程与指标采集及其本机资源生命周期由独立节点实现和验证，不在本项目提供采集节点程序。
- 依赖按服务声明，事件携带可追踪来源，宿主消费者不导入节点后端实现。专属新业务契约与消费者可由第三方宿主侧插件独立增加，默认进程外；远程代理保留断连与未知状态。
- 宿主订阅、代理、已消费游标 checkpoint 及消费缓存归属消费实例；节点负责采样任务、源位置解释、本机缓冲和进程。宿主游标与故障信号必须原子持久接收；分别清理资源，断连不代表采集停止，effect 清理不撤销已经发出的副作用探测。

- 新增采集器由独立节点项目实现，本目录记录其契约与接入要求，包括输入来源、目标身份、时效和可观测范围，不向通用框架加入供应商检测规则。以下采集实施约束由外部提供方落实，宿主保留对应验收和消费检查。
- 将采集器可用性与目标健康度分别表达；失联、缺失样本或过期数据必须报告未知，禁止默认为健康。
- 保留来源时间、接收时间及稳定事件标识；不能假定各节点时钟完全同步或事件严格有序。
- 对来源连续性变化、游标失效和断线缓冲明确恢复行为；无法补齐的数据区间需报告覆盖缺失。
- 采样、解析、缓冲和上报均有界；高频重复错误不能耗尽业务接收队列或阻塞其他目标采集。
- 从日志提取的指令、路径或模型文本均视为数据，不能转为操作授权或直接执行命令。
- 具有副作用的健康探测必须声明操作范围并走授权调用；普通采集权限不包含修复能力。
- 增加检测规则时说明误报、漏报及有效版本，使用脱敏故障样本验证异常和未知状态的区别。
- 实现后覆盖断线恢复、重复事件、权限失效和采集器退出，遵守 [架构恢复边界](../../docs/architecture.md)。
- 当前引擎通过 call_read_only 作有界单在途轮询，不是常驻日志推流；取消后等待原来源 future 收尾，不丢弃仍可能持有资源的调用。
- 目标判断、新鲜度和覆盖分别维护；空完整批次只说明覆盖，部分覆盖不得产生健康，重复/乱序不计数且不刷新年龄。规则比较成立代表健康，JSON pointer 和类型须严格校验。
- 使用节点相对年龄、宿主调用耗时及单调时钟判断过期；重启清除运行期健康和计数，保留故障及源代次游标。
- 缺失、过期和调用期限有独立定时检查；持久写失败停止采集并暴露错误。批内状态转换按序持久化，checkpoint 不得先于故障事实确认。
- 此阶段只持久记录、人工确认和凭新证据解除故障，不自动诊断或执行修复；确认不是恢复证明或授权。
- 通用发现只把提供方的有界目标 key 映射到可信模板，不接受提供方返回的路由、规则或任意参数；不向宿主加入供应商专属发现逻辑。
- 本域文档、配置示例和测试说明只使用中立 target/workload、provider observation 与抽象字段；不得记录具体产品、对象类别、实例、业务字段、故障样本、采集器私有路径、活动部署或跨项目真实环境验收。
- 已发现身份先持久登记再派发，按配置最大目标数终生占位；删除不得清空游标、解除故障或释放身份供另一目标复用。重启恢复身份后必须重新发现确认，不能沿用旧在场结论。
- 重启等待首次发现与完整清单确认缺失分开处理。等待期间禁止真实观察派发并保留启动宽限，首次重新确认在场不制造瞬时覆盖故障；明确缺失及时报告未知，宽限届满仍按既有时效检查判断。
- 有效部分清单只能增加或确认在场；只有无错误完整清单能标记缺失。非法、重复或超限批次整体拒绝，并展示发现错误，不将传输失败当目标删除。
- 动态任务登记与关闭串行；工作任务计数包括发现监督，零观察任务不表示可以关闭仍使用中的存储。取消后等待在途来源调用结束，成员代次和提交门共同拒绝删除后重现的旧响应。

## 源码拆分边界

- `mod.rs` 保持既有公开路径；配置、规则、观测契约、快照、共享状态、查询句柄、装配、调度、观测状态和发现各按 README 维护。
- `scheduler` 保留登记门与成员代次核验；`state` 保留故障信号和检查点的同次原子提交，不能让调度或公开句柄分别提交。
- `shared` 统一管理动态登记与关闭的串行门及 worker 所有权；等待当前任务结束不得简化成丢弃调用 future 或仅统计观察任务。
- 拆分内部字段和方法仅向 monitors 域开放，不能以重构为由增加公开状态迁移或跨域存储访问。
