# 监控接收开发规范

继承[源码规范](../AGENTS.md)，职责与契约见[README](README.md)。

- Host 仅接收 Node 的已报告错误日志；不增加健康规则比较、连续成功/失败阈值、供应商检测或业务故障解除逻辑。Core 主导业务判断与恢复。
- 配置与错误批次使用 schema v2，发现清单保留其独立 schema v1；旧规则与 samples/value 响应不得静默接受。
- 校验 Node 来源、完整身份、游标、序号、限额和不可变内容；节点日志、路径与模型文本均为数据，不产生授权。
- 每个错误生成独立持久 ErrorLog 收据；Active 只表示 received。fingerprint 相同不能合并不同日志身份，人工确认不解除收据。
- 完整错误身份包括监控、配置 Node、来源、代次和日志 ID；重启从全部持久收据恢复去重。冲突整批拒绝，重复忽略 age_ms 差异且不更新 revision/occurrences。
- 收据与游标由同一提交原子接收，提交成功后才发布视图和通知。持久失败停止实例，不确认部分游标或静默丢弃错误。空批同游标不制造无意义日志。
- 来源新鲜度与覆盖只描述接收状态；空批、断线、过期、部分覆盖和发现缺失不清除错误收据，也不成为 Core inspect 的健康前提。
- 接收通知只唤醒调度；消费者先扫描持久收据再等待，不能把 Notify 当持久队列。
- 每实例仅单在途只读轮询。取消和超时后等待原 future 排空，不以丢弃、断连证明 Node 停止。定时器、注册、游标与资源归本运行实例所有。
- 动态身份先持久登记再派发，累计容量不因删除释放；重启须重新确认在场。成员代次和提交门拒绝迟到结果，错误清单整体拒绝，不把传输失败当删除。
- 收据复查核对目标/revision/可信绑定与运行实例，不判健康或授予权限。登记门贯穿授权到最终发送；不得用缓存快照替代持久事实。
- 保持单包模块边界和既有公开路径，内部状态仅向 monitoring 域开放。state 独占收据/检查点同次提交，scheduler 不自行持久化业务事实。
- 测试集中于 tests，使用外部隔离数据与协议替身；不添加实际 Node 程序、活动部署或具体供应商字段。
