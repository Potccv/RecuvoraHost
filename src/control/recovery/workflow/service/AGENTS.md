# 恢复状态机规范

继承[恢复编排规范](../AGENTS.md)，接口见[README](README.md)。

- 准备阶段不得发起 I/O 或释放执行能力；许可必须由审批域产生，流程提交确认后才能返回执行效果。
- 历史和实时操作重复相同规则。恢复要求明确提交，保持原操作、审批期限、已消耗预算和永久隔离；恢复历史不得产生执行许可。
- 独立故障轮次、当前故障、目标身份与操作绑定必须校验；调用方提供的所有权事实不能替代实际互斥和原子版本检查。
- 业务终态与经验待交付分别表达；经验数据采用稳定幂等身份，失败/Unknown 隔离先随流程提交，不能依赖外部知识模块的可用性。
- 修复仅采用统一 Harness 会话；拒绝或明确失败不产生替代方案执行，Unknown 必须核实独立证据。
- 修改接口与语义同步[恢复参考](../../../../../docs/control/recovery.md)及集中测试，保持领域结构严格解析，不维护旧物理文件格式。

- 统一修复使用带明确委托的 Harness 请求；经验命中只提供参考，不跳过当前授权。具体动作发送前必须提交其完整内容，回执绑定已提交动作。
- 修复经验允许没有具体动作；脚本化评估是模型提案，不能继承本次业务成功为脚本验收。总结失败与业务终态分离，重试不能重新派发修复。
