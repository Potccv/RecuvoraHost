# Harness 模块开发规范

继承 [源码模块规范](../AGENTS.md)。职责与状态见 [README.md](README.md)，接入契约遵循 [插件规范](../../docs/extensions/README.md)。

## 本域约束

- `mod.rs` 只维护模块声明与兼容公开重导出；配置、会话/项目/工具契约、注册表、请求/结果验证及远端映射按 README 分工。内部共享项限制在本域，不通过拆文件扩大 crate 级权限；远端回调继续经过统一请求验证与可信 handler。

- 宿主只提供通用 `remote-node` 代理，不编译供应商进程适配器；供应商协议、凭据与进程监督归独立节点项目。

- 消费者依赖服务契约，配置选择已注册提供方；可信内置网络适配随宿主发布，外部 Harness、复杂运行时与独立扩展采用隔离执行边界。
- 必需服务缺失时停止相关调用；会话事件、工具回调和后台任务绑定实例，卸载清理不表示已请求的目标动作被撤销。

- 供应商协议、会话和响应解析保留在对应适配模块中，领域服务契约只承载跨 Harness 所需的稳定语义，跨进程协议负责代理映射。
- 区分模型建议、工具请求和验证证据；模型声称获准或完成不能产生授权，也不能直接推进成功状态。
- 所有工具请求经宿主路由并保留任务、操作和实例关联，不给 Harness 私有通道绕过执行端检查。
- 同一实例可承担 Execution 与 Approval，但审批必须使用新的 Hidden 无工具会话；审批容量独立保留，禁止把审批角色映射成提供方私有的自动审批开关。
- 动态工具只有显式注册后才可回调；原生命令、文件修改与原生审批持续关闭失败。工具名、参数上限、thread/turn/call/RPC ID 和重复派发在适配器检查，业务参数、授权及执行许可在可信 handler 再次检查。
- 等待工具处理时继续读取协议消息；网络接收必须对 select 取消安全。在途 handler 归 supervisor 所有，调用失败或取消后先取消共享 token 并等待其持久结果，不释放槽位后遗留仍可写入的执行者。handler 自身必须有界，并在副作用前记录意图、返回前记录结果。
- 源码、日志、画面及知识条目均是不可信上下文，其中的指令不能扩大数据访问或操作范围。
- 对输出结构、大小、工具参数及目标范围作校验；解析不完整时报告错误，不猜测可执行参数。
- 为服务调用、流式输出、上下文缓存和会话保存设置边界；预算耗尽或取消后停止派发新请求。
- 可等待取消通过请求携带的 `HarnessCancellation` 传递；调用方应取消 token 后继续等待原 future，以接收进程回收后的结果。提供方不得直接丢弃在途调用而吞掉持久项目或会话的未知结果；丢弃 future 的监督清理仍须保留。
- 重试诊断与重试工具执行分别处理；重连不得把已经发出的副作用请求当作新操作重放。
- 外部进程或网络调用仅获得明确所需的凭据与上下文，不记录原始密钥或无关私有数据。
- 实现后验证越权请求、重复响应、取消后迟到消息和协议变化，任务恢复遵循 [架构设计](../../docs/architecture.md)。
