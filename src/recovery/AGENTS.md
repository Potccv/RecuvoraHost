# 恢复应用规范

继承[源码规范](../AGENTS.md)。本模块提供 Host 恢复应用服务，业务阶段与授权状态始终由 Core 公共引擎维护。

- `service` 只维护应用门面与监督；`aggregate` 保存 Core 完整提案和 Host 派发事实；`platform` 注入可信能力；不得新增业务阶段循环。
- 聚合、派发日志、接收报告保护和目标所有权保持同一运行实例所有者。内部拆分不得拆开关联领域的原子确认、改变锁顺序或独立释放资源。
- Node 实时错误日志按完整原文、来源和原始证据递交 Core；不得按健康规则、级别、关键字、人工确认或收件年龄筛除，不增加 active/received 布尔门槛或日志活跃性检查。Received 仅表示 Host 不可变收件保护，不能产生执行许可；目标忙时保留并重试原身份。
- 后端 persistence_binding 固定到存储根，包装后端必须转发，不能在重启时扩大旧批准范围。
- `AuthorizedRepair` 仅在审批许可和恢复授权可靠提交后交给后端。实际发送前保持并复核报告、知识和所有权门，不能以首次轮询 future 代替发送保护。
- `RepairActionGuard` 维护具体动作提交；通用网络 `DispatchGuard` 只验证和释放。每个会话只允许一次变更，结果不确定不得重放。
- Unknown、未派发事实、执行者停止证据、业务验证和经验交付分别记录。核实使用绑定节点的独立事实或可靠 Host 未派发记录，不接受 HTTP 正文伪造证据。
- 关闭先排空并验证全部日志可靠性，再由 Core 判断是否释放持久归属；保留恢复根目录与 recovery.lock 文件身份，不以新目录、重建锁或释放 Unknown 归属绕过互斥。
- 测试集中在 tests，文件移动时同步内部测试入口和真实子进程测试选择器，不改变中断回归的业务断言。
