# 执行与验证模块开发规范

继承 [源码模块规范](../AGENTS.md)。职责与状态见 [README.md](README.md)，执行契约遵循 [插件规范](../../docs/plugins.md)。

## 本域约束

- 当前写入入口仅在 crate 内提供，由 Host repair 消费 Core 持久许可后调用；不向 Harness 暴露文件对象或绕过审批的执行方法。
- 以已打开句柄的实际路径核验对象，不能用第二次路径解析冒充对象身份；保持既有 UTF-8 文件、16 KiB 和准确白名单边界，新增动作单独定义授权和恢复语义。

- 执行与核验契约不依赖具体提供方内部实现；声明服务依赖及操作事件，由配置装配实现。
- 目标工具链、原生执行和独立扩展按故障范围隔离；内置纯 Rust 实现随宿主升级，不声称任意独立安装。
- 注册、操作订阅和执行资源归属实例；effect/dispose 清理不能冒充业务回退或取消已经生效的副作用。

- 操作接口须显式声明副作用、前置条件、目标范围、幂等性、核验方法及可用回退，禁止无上下文执行。
- 实际执行前验证授权、目标版本和执行令牌；路径规范化后仍须防止符号链接或目标变化越过授权范围。
- 参数按结构传递，避免将模型输出拼接为任意 shell 命令；命令能力仍受目标和工具范围约束。
- 配合节点先持久记录执行意图再产生副作用；插件私有日志不能替代权威自愈业务与节点执行记录。
- 已发出动作在超时或重启后先核验，不能以错误返回或未收到回执作为安全重放依据。
- 验证须检查预先约定的业务结果，命令退出码、补丁生成和模型声明均不能单独判定修复成功。
- 取消后清理子进程与在途操作并报告实际状态；确认旧实例无法再操作后才允许宿主释放锁或切换令牌。
- 修复 AI 仅能改获准目标与临时副本，不得修改 RecuvoraCore、嵌入应用、安装插件或扩大已有授权。
- 实现后覆盖部分完成、未知副作用、撤销授权和残留进程，遵守 [架构恢复流程](../../docs/architecture.md)。
