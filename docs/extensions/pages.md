# 插件独立页面约定 v1

本约定定义独立插件向 Host 声明页面入口、Host 绑定部署地址、客户端展示跳转按钮的接口。它是[扩展协议 v1](protocol.md)上的可选能力，不改变共同消息、节点角色或业务执行权限。Host 已提供部署配置、描述读取与认证目录接口；外部 UI 的按钮及浏览器打开由客户端实现，验收边界见 [HOST-004](../status.md#host-004)。

## 范围与职责

插件自行提供网页、静态资产和业务 API，自行管理进程、登录与页面业务授权。Host 校验页面描述并生成导航目录；统一 UI 使用目录中的地址在外部浏览器或新标签页打开。插件页面、协议端点可以由同一个进程提供，不要求同端口、同来源或同一访问路径。

本版本只约定静态页面入口，不提供 iframe、插件脚本注入、资产代理、单点登录、动态目标参数、页面安装或进程启动。页面存在及按钮可见均不产生 Host 的执行权限。独立进程自己的操作仍由插件和部署方约束；纳入 Host 恢复流程的操作继续遵守[审批规则](../approval.md)。

## 能力发现与方法绑定

插件在 Ready 的 `capabilities` 中声明 `recuvora.ui_links.v1`。这个字符串是 Host 识别的能力标识；实际业务契约必须位于该插件获准拥有的非 `recuvora` 命名空间，例如 `com.example.workload.ui`，契约 `version` 为 1。

Host 在已登记的插件契约中查找名为 `describe_ui_links` 的方法。启用本能力必须同时满足：

- 扩展为已启用、已登记的 `kind: plugin`。
- 全部契约中恰好有一个同名描述方法，其契约版本为 1，归属当前插件，且 `read_only: true`。
- 精确的契约 ID、版本和方法已列入可信配置的 `allow_calls`。
- 输入 schema 接受固定对象 `{"schema_version":1}`，输出 schema 接受下文的完整响应；Host 同时校验声明 schema 与本约定的语义限制。
- 可信部署明确启用页面入口并提供地址绑定；能力声明本身不能启用导航。

未声明能力表示不提供页面。声明能力但方法缺失、重名、归属错误或未获准时，本能力登记失败；有效的其他业务能力继续按其规则处理。非法的整体配置或基础协议消息仍按原规则拒绝，不能利用可选能力绕过基础校验。

该方法复用 Call/Result/Error，不增加消息类型，不向 Ready 添加页面列表、URL 或可变 revision。Host 使用专门的描述调用路径：固定输入、不提供任何 callback 处理器、每插件最多一个在途页面描述调用、正常调用期限 5 秒且容量满立即报告忙。达到期限后仍按共同协议取消和排空，收尾完成前不释放调用资源或派发替代调用；不自动重试。页面描述失败不得占用审批容量或隐式调用节点查询。

声明此能力后，`describe_ui_links` 不得经通用只读查询或其他 descriptor 路径调用；HTTP 使用下文的专用刷新入口，避免绕过固定输入、无回调及单调用容量边界。

## 请求与响应

请求 params 固定为 `{"schema_version":1}`，不接受其他字段。响应为 Result 的 `result` 对象，不重复携带插件身份；身份来自已认证连接及登记绑定。

| 字段 | 类型与规则 |
| --- | --- |
| `schema_version` | 必填整数，精确为 1 |
| `revision` | 必填字符串，符合共同协议 `valid_id`；作为描述内容的不透明版本标识，不进行数值或时间排序 |
| `pages` | 必填数组，0–16 项；空数组表示插件明确没有页面 |

每个 page 的字段如下，所有层级拒绝未知字段，可选字段缺省时省略，显式 null 不合法。

| 字段 | 类型与规则 |
| --- | --- |
| `id` | 必填协议 ID；在插件内唯一且跨刷新稳定，不因标题或部署地址改变而改变 |
| `title` | 必填非空白纯文本，最多 128 UTF-8 字节 |
| `description` | 可选纯文本，最多 1024 UTF-8 字节 |
| `entrypoint` | 必填协议 ID，引用可信部署中的页面基础地址绑定，如 `web` |
| `relative_url` | 必填字符串，最多 2048 UTF-8 字节，按下文解析；空字符串表示基础地址本身 |
| `open_mode` | 必填，唯一合法值为 `external` |

响应紧凑 JSON 编码最多 32 KiB；所有文本拒绝 U+0000–U+001F 和 U+007F。标题和说明按纯文本展示，不解释 HTML、Markdown 或可执行内容。数组顺序决定默认展示顺序，不授予页面覆盖统一 UI 导航的能力。

插件在描述内容改变时必须更换 revision，不得复用旧 revision 表示不同内容。Host 至少与上一已接受快照比较，相同 revision 必须对应相同字段值和页面顺序；JSON 对象键顺序不参与内容比较，不要求 Host 保存无界 revision 历史。revision 不是缓存有效期、身份凭据或业务记录 revision。收到不同 revision 时仍执行完整校验，不能据此扩大已配置的地址或权限。

完整 Ready、方法 schema、Call、Result 和拒绝样例见 [JSON 样例](examples/pages.json)。共同 schema 的 maxLength 按 Unicode 标量值计数，不能替代本约定额外的 UTF-8 字节限额、ID、唯一性和 URL 校验。样例不代表运行会话顺序，也不证明方法已经获准或页面已经可访问；expected_error 是样例分类，不新增 wire 错误码。

## 可信部署地址绑定

部署方为每个插件提供独立的 `entrypoint → public_base_url` 映射，必须明确启用。这里的 public 表示用户浏览器可访问的地址，可以是内网地址，不要求公网。映射是可信部署数据，不能从插件描述、观察数据或模型文本自动建立。

对应 `ExtensionsConfig.extensions[]` 的可选 `ui_links` 对象：`enabled` 缺省为 false，`entrypoints` 缺省为空映射，最多 16 项，键为共同协议 ID，值为基础 URL 字符串。未配置时不会调用页面描述。`kind: node` 不得启用页面或填写非空绑定；无效绑定即使尚未启用也按配置错误拒绝。完整占位模板见 [extensions.pages.example.json](../../profiles/extensions.pages.example.json)。

```json
{
  "ui_links": {
    "enabled": true,
    "entrypoints": {
      "web": "https://plugins.example.com/workload/"
    }
  }
}
```

例如插件的 `web` 绑定到 `https://plugins.example.com/workload/`，`relative_url: "dashboard"` 解析为 `https://plugins.example.com/workload/dashboard`。相同插件部署在另一环境时只需调整绑定。不得从 ws/wss/http/https 协议 endpoint 自动推导网页地址；远端插件也不能用自身的 localhost 替代用户浏览器可达地址。

基础地址必须是含 host 的绝对 HTTPS URL；可信部署可显式选择 HTTP。两者都拒绝用户信息、query、fragment、端口 0、空白、控制字符和反斜杠；路径必须以 `/` 结束。HTTPS 的选择不表示 Host 为页面可达性、内容或业务正确性作保证。

页面地址解析必须满足：

1. 使用 URL 解析器将 relative_url 相对于配置的基础地址解析，不使用字符串拼接。拒绝空白、控制字符、反斜杠、非法百分号转义、带 scheme 的地址、以 `/` 开头的绝对路径或网络路径引用。
2. 路径段不能为 `.` 或 `..`。基础路径与相对路径都要在规范化前检查原始路径，并对每个路径段进行一次百分号解码后复查；拒绝解码后包含 `/`、`\`、`%` 或控制字符的路径段，防止编码分隔符、嵌套编码与路径穿越。
3. 解析后的 scheme、host 和有效端口必须与基础地址一致；规范化路径必须位于该基础目录中。基础目录以 `/` 结束，不能用无目录边界的字符串前缀接受相邻目录。
4. 相对地址可以包含固定 query 和 fragment，例如 `logs?level=error` 或 `#/dashboard`，但不得包含任何凭据、令牌、个人数据或待执行动作。页面 GET 应符合无业务副作用的导航语义；本版本不支持模板替换或根据目标生成参数。
5. 最终 URL 最多 4096 UTF-8 字节。Host 不主动抓取页面、跟随网页重定向、检查登录态或反向代理页面。上述检查限定初始导航地址；插件服务自身后续的重定向、页面内容与授权由插件和部署负责。

没有匹配 entrypoint 时，页面标记为 `binding_missing`，不得回退到协议 endpoint 或其他绑定。配置了非法基础地址时按配置错误拒绝，不静默忽略。任意页面字段或相对地址不合法时，整个描述响应无效，不部分发布该响应。

## Host 向 UI 提供的导航对象

`GET /api/v1/ui/catalog` 保持 `schema_version: 1` 和既有 `views` 数组，新增 `external_links` 与 `link_statuses`。Host 为通过校验且完成绑定的页面生成以下对象，放入扁平的 `external_links` 数组；`views` 仍只包含声明式监控视图。

| 字段 | 来源与含义 |
| --- | --- |
| `kind` | 固定 `external_link`，与声明式 renderer 区分 |
| `plugin_id` | Host 登记的插件实例 ID |
| `page_id` | 插件 page.id；与 plugin_id 一起构成稳定导航身份 |
| `title`、可选 `description` | 已校验的页面纯文本 |
| `url` | Host 解析并校验后的绝对地址 |
| `open_mode` | 固定 `external` |
| `descriptor_revision` | 本次有效描述的 revision |

页面目录通过认证的 Host API 提供，读取要求 `extension.read`；独立页面入口不附带 `monitor.read` 要求。已有监控视图继续遵循其原有权限。部署方可停用整个插件的页面入口；插件不能在描述中授予权限或自动修改 Host 的 allowed_origins。目录只返回该调用者获准看到的入口。

`link_statuses` 每插件一项，包含 `plugin_id`、下文定义的 `status`、可空的 `descriptor_revision` 和 `error`，以及 `unavailable_pages` 数组。未绑定页面表示为 `{"page_id":"logs","entrypoint":"web","reason":"binding_missing"}`。失败时保留的 revision 仅用于诊断，不表示仍有可点击链接；错误为有界、不含提供方原始文本或凭据的说明。仅具备 `extension.read` 的调用者可以读取页面目录，其 `views` 为空；缺少 `extension.read` 返回 403。

UI 显示插件归属和页面标题，明确该按钮会打开外部页面；只使用目录中的 url，不在浏览器端重新拼接 endpoint 或 relative_url。Web UI 用新标签页打开并采用 `noopener,noreferrer`；桌面 UI 使用受控的 http/https 浏览器打开能力，不将链接交给 shell 命令解释。UI 不发送 Host Bearer、协议端点凭据或自动登录参数。页面登录由插件负责。

目录不对外部页面标注 `read_only: true`：描述方法是只读的，但插件页面可能包含自身授权的操作。链接存在不表示页面在线、用户已登录或业务健康。

## 刷新、失败与资源归属

Host 在页面能力登记及部署绑定完成后读取描述，初始化阶段最多并发读取 4 个插件，每插件仍限一个在途描述；保存本运行实例内的有效快照。目录读取使用该快照，不因每个浏览器请求而再次调用插件。管理方可通过 `POST /api/v1/ui/plugins/{plugin_id}/links/refresh` 显式刷新，正文必须为 `{}`，要求 `extension.read`。并发刷新共享每插件一个调用的容量限制，不积累无界队列，不自动轮询或重放。当前不提供配置热重载或在线停用 API；修改插件启用状态或部署绑定后需重启服务以建立新的登记实例。

刷新返回 `{"schema_version":1,"plugin":快照,"auto_retry":false}`。快照包含 `link_statuses` 中的全部字段以及该插件的 `links` 数组；HTTP 200 只表示取得刷新结果，客户端还须读取 `plugin.status`。已派发描述调用失败或响应不合法时，200 响应中状态分别为 `unavailable` 或 `invalid_response`，`links` 为空。未声明、未启用或登记无效返回相应状态且不调用插件。未知插件返回 404，非法 ID 返回 400，结构错误正文返回 422，容量忙返回 409，服务无法派发返回 503；认证失败为 401，缺少权限为 403。客户端不得因非成功状态自动重发刷新。

成功响应经完整校验后原子替换旧描述；发布前再次核对插件登记实例、启用状态和地址绑定，丢弃属于旧实例或旧配置的迟到响应。空 pages 清空页面入口，删除页面 ID 撤下相应按钮。刷新期间可以继续提供上一有效快照；已开始的刷新失败后旧描述仅供诊断，下一次目录响应不得继续发布其可点击链接。容量满而未派发的重复刷新不改变快照或现有调用。重新获取有效描述后恢复。未主动刷新时的快照只代表已登记描述，不代表网页当前可达。

Host 区分以下能力状态；它们通过目录和刷新响应提供，错误文本有界且不含凭据。

| 状态 | 含义与处理 |
| --- | --- |
| `not_declared` | 未声明能力，不产生入口 |
| `disabled` | 可信部署未启用或已停用，不派发描述调用，不产生入口 |
| `invalid_registration` | 描述方法或白名单不满足约定，不产生入口 |
| `unavailable` | 插件未登记成功、描述调用失败或刷新失败，不提供可点击链接 |
| `invalid_response` | 响应结构、地址、revision 一致性等校验失败，不发布该响应 |
| `ready` | 描述有效；仅完成绑定的页面产生链接，空清单同样可以 ready |

`binding_missing` 是单页绑定状态，不是插件业务故障。插件页面失效不解除故障、不取消已授权操作，也不影响有效的其他契约。插件或页面入口停用、绑定撤销生效后，Host 必须撤销相应快照中的可点击入口；浏览器已打开的页面不会因此被关闭或失去其插件侧权限。

Host 重启重新读取描述，不从持久旧快照恢复有效页面入口。关闭时停止新描述派发，请求取消并等待在途调用收尾；关闭连接不负责停止插件网页服务或插件进程。

## 版本与兼容检查

本能力使用共同协议版本 1、能力标识 `recuvora.ui_links.v1` 和描述 schema_version 1。旧 Host 可以按既有规则登记合法自定义只读契约，但不会因此提供页面导航。不支持此能力的客户端不能被视作已支持跳转按钮。

新增不兼容描述字段、页面打开模式或地址语义时应定义新的能力/schema 版本及明确的方法选择规则，不能向严格 v1 对象直接加入字段。描述内容通过方法响应更新，不改变握手声明；契约、schema 或能力集合变化仍遵循共同协议的重新登记规则。Host 到 UI 的目录扩展须独立检查既有客户端兼容性，不能自动提升或覆盖现有 monitoring_v1 renderer 的含义。

集中检查维护能力与方法唯一绑定、schema 和白名单、禁止回调、描述调用容量与取消、未知字段及限额、重复页面 ID、相同 revision 内容冲突、基础目录与编码穿越、HTTP/HTTPS 和 SPA fragment、缺失绑定、无监控权限时的入口读取、停用与刷新失败撤下链接，以及既有监控目录兼容。协议/Host 检查归入 tests 集中目标；真实网页、登录和跨机跳转由独立插件及 UI 验收。实际检查结果以 [HOST-004](../status.md#host-004)为准。
