# 插件与服务接口约定

本目录按职责维护[网络接入](connection.md)、[共同协议](protocol.md)、[节点业务接口](nodes.md)、[独立页面](pages.md)、[集成实现](integration.md)和[JSON 样例](examples/README.md)。接口版本写在正文与消息中，文件路径保持按主题稳定。

各模块通过服务接口协作，Host 按声明的依赖顺序启动模块，并管理它们的运行实例。源码模块、插件包、运行实例、服务和工作进程各有自己的标识，不要求一一对应；Host control 校验恢复状态迁移，Host 保存完整历史并提供业务接口。

## 内置模块

可信 Rust 模块随嵌入应用共同编译。`ServiceKey` 精确匹配名称、主版本和作用域；`ModuleMetadata` 声明提供与必需服务，运行管理模块在启动前拒绝缺失、冲突和依赖循环。配置只选择已经编译的实现，新代码需要更新应用；没有任意原生动态库或代码热安装。

服务、事件订阅、后台任务与清理函数（disposer）由所属模块实例管理。事件队列有容量上限且不保存到磁盘，不能替代授权或恢复日志。取消通知和超时限制无法解决阻塞、死锁或恶意本机代码；需要隔离运行的功能由独立外部进程提供。清理资源不会撤销已经发生的目标修改。

## 独立扩展与节点

外部扩展使用[协议 v1](connection.md)。`kind: node` 表示能力提供方，`kind: plugin` 可在获准命名空间登记版本化业务接口约定和消息结构（schema），并使用配置允许的节点只读方法。宿主侧插件是逻辑角色，默认进程外；不是必须同进程的 Rust 模块。

插件不能占用 `recuvora` 保留域或冲突命名空间。节点只能实现已经登记且完全匹配的接口约定。配置中的调用白名单、接口约定版本、输入输出 schema 与容量均需通过校验。缺失接口约定或能力不兼容只使相关实例不可用；配置本身非法则拒绝启动。

第三方业务字段与解释保留在独立插件，不进入通用核心。`recuvora.monitoring_view.v1` 能力声明及 `describe_monitoring_view` 只读描述由 Host 校验，通过 UI catalog/view 路由使用；Host 不执行插件页面或脚本，官方 UI 仍作为外部资产托管。

插件自行提供网页时，页面声明、部署地址绑定及外部跳转遵循[插件独立页面约定 v1](pages.md)。该能力与声明式监控视图独立，Host 与 UI 接入状态见 [HOST-004](../status.md#host-004)。

Host 提供通用 `remote-node` Harness 代理，不包含具体供应商节点。外部项目独立选择语言、依赖、构建和发布，只需遵守共同协议。当前没有自动下载、安装市场、签名分发、在线热升级或对任意第三方 API 的兼容承诺。

## 授权与事实

安装、启用、接口约定登记、调用权限和业务授权各自独立。schema 只校验消息结构，不证明事实真实或产生写权限。普通第三方调用当前只读；真实写操作必须通过可信 Harness 工具处理链，由 Host control 根据已保存的审批记录和执行端再次校验。

执行和审批可以使用同一 Harness 实例，但会话、上下文、工具权限和容量必须隔离。审批为 Hidden 无工具会话；提供方私有自动审批不能替代核心审批。模型、日志、修复经验和观察结果均为证据输入，不是管理指令。

服务不可用、协议错误或取消后保留实际结果语义，已派发副作用的不确定结果为 Unknown。重连或配置重建不赋予旧请求新的执行权。节点负责其实际机器的资源与执行事实，宿主不把远端路径当成本机路径核验。

## 关闭与升级

停用先拒绝新派发，再等待正在处理的调用结束、记录结果、撤销服务和清理实例资源。连接关闭不等于远端停止；释放冲突资源前必须确认旧执行者不能继续操作。负责最终判定的关键服务升级必须受控停机与恢复，不能形成双重授权、双重调度或日志分叉。

当前版本协商、schema 子集与传输限额以[协议文档](connection.md)为准。自动测试范围见[实现状态](../status.md)，配置例子见 [profiles](../../profiles/README.md)。
