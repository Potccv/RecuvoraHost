# 宿主文档规范

继承[项目规范](../AGENTS.md)。

## 内容归属

- 根 README 是项目定位、运行入口和文档导航；根 AGENTS 是每次开发都需遵守的规则。详细字段、接口表和局部实现说明不放入根入口。
- `docs/README.md` 按读者任务组织导航；`development.md` 说明开发准备与检查流程；`architecture.md` 说明职责、服务装配和生命周期。
- 文档按主题命名，相关专题分别归入 `extensions/` 和 `api/`；版本、状态及格式差异写在正文或分类目录中，不在文件名堆叠 `v1`、`vectors`、`rust-api` 等后缀。JSON 样例集中在所属专题的 `examples/`。
- CLI、HTTP、配置、监控、恢复和审批各自维护专题说明；协议规范、业务 JSON 与 Rust API 分别服务外部实现者和嵌入调用者，不混为同一兼容承诺。
- 模块 README 维护自身职责、配置、失败与资源释放规则；局部 AGENTS 只补充该目录的开发约束，不重复整份上级规范。
- 当前能力、已知缺口和验证范围集中在 `status.md`，不在架构与接口说明中分散维护测试数量或按日期排列的修改过程。
- 同一事实只在所属文档详细说明，其余使用相对链接。Core 仅作为公共领域 API 依赖说明；不复制其内部模块说明或测试结论。恢复服务、持久存储、调度和关闭须明确归属本项目。教程按先决条件和操作顺序写，参考文档按查询主题写；段落一行，表格和代码块保留结构。

## 内容与校验

- 精确区分 Host 应用装配、Core 库能力、外部网络节点与 UI 客户端，不能把依赖已有能力写成 Host 已提供入口。
- CLI 与 HTTP 默认编译，不保留旧 feature、UI/Tauri构建、stdio/SSH节点启动说明或失效源码链接。
- 说明 endpoint 网络会话必须兼容 扩展协议 v1，不能把任意 REST/模型地址当作节点；旧 command 不自动迁移。
- 身份、权限、revision、持久批准、Unknown 和业务恢复分别说明，批准不隐式执行，回执未知不自动重放。
- 文档只含当前实现与中立模板，不写外层布局、本机绝对路径、实际令牌或跨项目验收流水。
- 命令与字段依据现有代码校验；相对链接保持项目内有效，编译/协议替身不能声称实机业务验收。
- 移动内容时同步更新相对路径和指向标题的锚点，保留调用前提、失败语义、所有权与限制；不照搬其它项目的包布局、命令、发布流程或未经本项目验证的能力。
